# Yandex Station BLE Gateway

[English version](README.md)

Локальное голосовое управление чайником Redmond SkyKettle RK-G214S через Яндекс Станцию Мини первого поколения (YNDX-0004). Проверенный чайник объявляет себя по BLE как `RFS-KKL003`. Для связи используются встроенный контроллер Bluetooth и штатный стек Broadcom BSA, а для распознавания речи и озвучивания ответов — Quasar.

## Голосовые команды

| Фраза после «Алиса» | Действие |
| --- | --- |
| «Какая температура воды в чайнике?» | Измерить и озвучить температуру воды. |
| «Какой статус чайника?» или «Как там чайник?» | Сообщить состояние нагрева и примерную температуру. Во время нагрева также озвучить целевую температуру. |
| «Вскипяти воду в чайнике» | Запустить кипячение из режима ожидания и подтвердить запуск. |
| «Нагрей воду в чайнике до 65 градусов» | Запустить штатный нагрев из режима ожидания. Допустимый диапазон — 35–90 °C. |
| «Прекрати нагрев чайника» | Остановить нагрев и подтвердить остановку либо сообщить, что нагрев уже выключен. |

Сначала программа пытается открыть GATT-соединение напрямую. При ошибке она один раз сканирует эфир и повторяет попытку. Для этой прошивки нужен проверенный непустой образ кэша GATT. Пустой ответ ранее приводил к остановке BSA. [Исследование Bluetooth](docs/bluetooth-stack.md)

## Сборка в WSL

Понадобятся GNU Make, Python 3, кросс-компилятор GCC для ARM hard-float со статической libc, ARM binutils и доступ к Станции по SSH от имени root. Скопируйте библиотеку со своей Станции в каталог сборки.

```sh
mkdir -p build/phase1
ssh -F "$HOME/.ssh/config" -T station 'cat /system/workdir/lib/libbsa.so' > build/phase1/libbsa.so
make
```

Переменные `ARM_CC` и `ARM_CC_FLAGS` позволяют выбрать локальный кросс-компилятор и его sysroot. `CROSS_COMPILE` задаёт префикс binutils.

`make check` проверяет согласованность ссылок на версию, Python-скрипты, синтаксис shell и C-клиент без ARM-тулчейна и библиотеки BSA. `make test` запускает модульные тесты и регрессионные тесты с фейковым Quasar: распознавание, отмена, таймауты и привязка. Файл `VERSION` — единственный источник версии пакета: `pack-yam.sh` берёт из него имя архива и версию в `yam.yaml`. Для выпуска обновите `VERSION` и строку `version:` в `packaging/yam/yam.yaml`, затем следуйте [чек-листу релиза](docs/release.md).

Таймауты настраиваются переменными `KETTLE_JOB_TIMEOUT_MS`, `KETTLE_PAIR_TIMEOUT_MS`, `KETTLE_STOP_GRACE_MS`, `KETTLE_SESSION_TIMEOUT_MS` и `KETTLE_SPEECH_TIMEOUT_MS`. Значения по умолчанию и поток привязки описаны в [архитектуре](docs/architecture.md).

## Запуск одной сессии

```sh
KETTLE_ADDRESS=AA:BB:CC:DD:EE:FF scripts/run-station.sh /absolute/path/to/kettle.key
```

По умолчанию используется SSH-псевдоним `station`. Другую цель можно передать вторым аргументом, а другой конфигурационный файл SSH — через `SSH_CONFIG`. Если путь к ключу опущен, используется `build/phase1/wsl-kettle.key`. Скрипт ждёт одну команду и после завершения сессии удаляет временные файлы со Станции. Для следующей команды запустите новую сессию.

## Голосовая привязка

Запустите обычную сессию, указав путь, по которому ключа пока нет.

```sh
KETTLE_ADDRESS=AA:BB:CC:DD:EE:FF scripts/run-station.sh /absolute/path/to/kettle.key
```

Оставьте чайник на подключённой подставке в режиме ожидания и отключите телефон от чайника. Произнесите любую настроенную команду. По просьбе Алисы удерживайте кнопку питания чайника до трёх коротких сигналов. Пока открыто окно привязки, Станция пытается пройти аутентификацию и прочитать статус.

После голосового подтверждения повторите исходную команду в той же сессии. При завершении WSL сохраняет проверенный восьмибайтный ключ по указанному пути с правами `0600`. При неудаче временный ключ остаётся в файле `.pending` для повтора. Существующий ключ сохраняется. Храните ключи в закрытом каталоге или вне файлов, отслеживаемых Git.

Для привязки из терминала используйте тот же `KETTLE_ADDRESS` и запустите `scripts/run-station.sh --pair /absolute/path/to/kettle.key`.

## Настройка фраз

Измените [config/kettle-phrases.conf](config/kettle-phrases.conf) или укажите другой UTF-8 файл через `KETTLE_PHRASES`. Каждая строка связывает фразу с действием. Для одного действия можно задать несколько фраз.

```ini
temperature=какая температура воды в чайнике
temperature=сколько градусов в чайнике
status=какой статус чайника
status=как там чайник
stop=прекрати нагрев чайника
boil=вскипяти воду в чайнике
heat=нагрей воду в чайнике до
heat.75=нагрей воду в чайнике для термоса
```

При сопоставлении учитывается вся фраза, а регистр, начальное «Алиса» и конечная пунктуация игнорируются. Ошибочные строки или дубликаты после нормализации мешают запуску. Правки вступают в силу в следующей сессии. Проверяйте кипячение под присмотром и с водой в чайнике.

Запись `heat.<градусы>=<фраза>` задаёт фиксированную цель от 35 до 90 °C. Для термоса по умолчанию используется 75 °C. При обновлении старой конфигурации встроенная фраза для термоса действует до появления пользовательской команды с фиксированной температурой. Чтобы применить правки установленного пакета, перезапустите службу.

## Установка через Alice Homebrew

Загрузите локальный пакет `redmond-kettle-<версия>-yandexmini.yampkg` (версия берётся из файла `VERSION`) через Alice Homebrew. Профиль `yandexmini` предназначен для Станции Мини первого поколения. Пробы используют штатный загрузчик ARM hard-float и библиотеку BSA на Станции.

Перед обновлением завершите сессии, запущенные на переднем плане, через Ctrl+C. Установщик запускает фоновую службу и создаёт `/etc/init.d/S99redmond-kettle` для автозапуска. При первой установке или обновлении с 1.1.x впишите BLE-адрес чайника одной строкой в формате `AA:BB:CC:DD:EE:FF` в `/data/yam/etc/lynx.redmond-kettle/device.conf`, затем перезапустите службу. Спросите Алису о температуре воды и, если она предложит привязку, выполните её и повторите вопрос.

Для того же чайника сохранённый ключ продолжит работать. Чтобы сменить чайник, остановите службу, переместите прежние `kettle.key` и `kettle.key.pending` из каталога состояния, поменяйте адрес и перезапустите службу.

Чтобы узнать адрес, запустите сканер из WSL и найдите `RFS-KKL003` в результатах. Если таких устройств несколько, сравните результаты с чайником на подставке и без него.

```sh
mkdir -p build
ssh station 'cd /tmp && LD_PRELOAD=libpthread.so.0 LD_LIBRARY_PATH=/system/workdir/lib /data/yam/share/lynx.redmond-kettle/libexec/discovery' > build/scan.bin
python3 scripts/decode-bsa-discovery.py build/scan.bin
```

Управление службой и просмотр журнала из оболочки Станции:

```sh
/data/yam/bin/redmond-kettle status
/data/yam/bin/redmond-kettle restart
grep redmond-kettle /var/log/messages
```

Служба пишет в syslog с тегом `redmond-kettle`. На этой прошивке `/var/log` указывает на `/tmp`, поэтому при перезагрузке журнал очищается.

Перед удалением пакета выполните `/data/yam/bin/redmond-kettle stop`. В YAM v2 нет обработчика удаления, поэтому запись автозапуска остаётся и завершается сразу, если пакет отсутствует. Чтобы отключить автозапуск, переместите `/etc/init.d/S99redmond-kettle` за пределы шаблона `S??*`. Переустановка восстановит запись.

- Фразы хранятся в `/data/yam/etc/lynx.redmond-kettle/phrases.conf`. Переустановка сохраняет файл. Для применения правок перезапустите службу.
- Проверенный ключ хранится в `/data/yam/var/lynx.redmond-kettle/kettle.key` с правами `0600`. Рядом остаётся файл `.pending` для повторов после неудачной привязки. После проверки ключа следующий запуск службы очищает этот файл.

Соберите пробы BSA кросс-компилятором ARM hard-float, совместимым со Станцией. Для голосового клиента используйте компилятор ARM hard-float с musl, а для упаковки — официальный инструмент YAM.

```sh
make all
make -B build/phase1/alice-kettle ARM_CC=arm-linux-musleabihf-gcc
MUSL_COPYRIGHT=/path/to/musl/COPYRIGHT \
  YAM_PROFILES=/path/to/yam/platforms scripts/pack-yam.sh
```

Укажите `YAM_PUBLISH`, если упаковщик находится вне `PATH`, и возьмите файл `COPYRIGHT` именно от версии musl, с которой сделана сборка.

Пока выполняется команда чайника и Quasar свободен, индикатор пульсирует розовым. Перед голосовым ответом пульсация прекращается. Чтобы отключить её на одну сессию, остановите фоновую службу и запустите `KETTLE_ACTIVITY_PATTERN= /data/yam/bin/redmond-kettle run`.

## Публикация в YAM Registry

Имя пакета — `lynx/redmond-kettle`, целевой профиль — `yandexmini`. В архив входят лицензия MIT проекта и уведомления статически связанной musl. Библиотека BSA берётся со Станции.

Задайте `YAM_AUTHOR_KEY_FILE` и `YAM_PUBLISH_TOKEN` в окружении WSL и отправьте собранный архив.

```sh
yam-publish publish --source packaging/yam --target yandexmini \
  --artifact "build/dist/redmond-kettle-$(cat VERSION)-yandexmini.yampkg"
```

[Руководство по публикации YAM](https://github.com/nyakokitsu/yam/blob/main/docs/PUBLISHING.md)
